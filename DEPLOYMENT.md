# Free demo deployment (Render)

This blueprint deploys the existing FastAPI API as a Docker web service. It
keeps the existing Node.js + snarkjs subprocess verifier intact; it does not
replace server-side Groth16 verification with a browser-side trust decision.

## Required free-tier services

1. A Render account connected to this GitHub repository.
2. A Redis-compatible endpoint on a free tier (for example, an Upstash Redis
   database). The API requires shared Redis for replay protection and fails
   closed if Redis is unavailable.
3. The Firebase Realtime Database secret used by the existing user registry.

The Render web service is configured with the free plan. Free web services may
sleep when idle, so the first request after inactivity can take longer. This
is acceptable for an occasional resume/interview demo and avoids a monthly
hosting charge.

## Deploy

1. In Render, choose **New + → Blueprint** and select this repository.
2. Render detects `render.yaml` and creates the `zerify-api` web service.
3. Create a free Redis database with your chosen Redis provider. Copy its
   connection URL into the Render service's `REDIS_URL` environment variable.
4. Set `FIREBASE_DATABASE_SECRET` to the existing Firebase Realtime Database
   secret. Do not commit either secret to GitHub.
5. Wait for the Docker build and deploy to finish.
6. Open `https://<your-render-service>.onrender.com/api/health`. A healthy
   response contains `"status":"ok"`.

## Connect the dashboard

After the API is deployed, set this Cloudflare Pages/Workers build environment
variable for the Next.js dashboard:

`NEXT_PUBLIC_API_BASE_URL=https://<your-render-service>.onrender.com/api`

Redeploy the dashboard after changing the variable. The frontend appends
`/verify-proof`, so the `/api` suffix is required.

## Verification checklist

- `GET /api/health` returns HTTP 200.
- A proof with mismatched public signals is rejected.
- A valid synthetic proof is accepted once.
- Submitting the same valid proof and nonce again is rejected as a replay.
- Redis being unavailable causes verification to fail closed (HTTP 500), never
  to silently accept a proof using process-local memory.

Do not use a real Aadhaar image or personal identity data for deployment tests.
Use a synthetic test identity and a proof generated by the project's circuit.
